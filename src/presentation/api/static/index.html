A blog backend where the schema is versioned and every read is eager.

FastAPI, SQLAlchemy 2 and Alembic against a pooled Supabase Postgres connection. Seven tables, three migrations deep, and zero surprise queries at serialisation time.

Built to fail loudly

The defaults here are the ones that hide problems: connections are verified, the ORM refuses lazy loads, and schema drift has somewhere to be caught.

Versioned migrations

A real baseline plus ordered, reversible upgrades. alembic check fails the moment a model and the database disagree.

Eager by default

Author, comments, topics and references load with the blog. Reverse sides are lazy="raise", so an N+1 can never creep back in unnoticed.

One connection source

The app and Alembic both read the same DATABASE_URL, so migrations can never run against a different database than the app.

Endpoints

Interactive documentation lives at /docs.

  • POST /blogs Create a post
  • GET /blogs List posts
  • GET /blogs/{'{ blog_id }'} Fetch one post with its full graph
  • PATCH /blogs/{'{ blog_id }'} Partial update
  • DELETE /blogs/{'{ blog_id }'} Delete a post
